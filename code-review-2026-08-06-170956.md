# Extensive Code Review — Caldera Engine

**Date:** 2026-08-06 17:09
**Scope:** `Caldera/Source` + `Sandbox/Source` (Thirdparty vendored libs excluded)
**Method:** Read every engine file (34 headers + all sources), clean-built with clang (green: `libCaldera.dll` + `Sandbox.exe` produced), and ran a `-Wall -Wextra` syntax pass that compiler-confirmed several findings. A second reviewer agent independently validated the same set.

Severity key: 🔴 **CRITICAL** (crash / UB / guaranteed failure) · 🟠 **HIGH** (leak / broken path) · 🟡 **MEDIUM** (design / fragility)

---

## 🔴 Critical

### 1. `Vector` has no copy/move semantics → double-free, corrupted refcounts, UAF
**File:** `Core/Containers/Vector.hpp`

- User-provided destructor + *implicit shallow copy* → every copy (init-from-ref, return-by-value, `pushBack`'s `copyMemory`) duplicates the raw `mData` pointer. Two destructors free the same block.
- `RenderPacket.meshes` is `Vector<MeshAsset>` and `MeshAsset` holds `Ref<Buffer>` (`shared_ptr`) → `pushBack`/copies **byte-copy a shared_ptr**, corrupting refcounts.
- `ModelLoader::loadMesh` does `return Mesh{ vertices, indices };` → locals free the buffer at return, the returned Mesh points at freed memory. **Double-free + UAF the moment any mesh loads.**

**Fix:** Implement the rule of five (deep-copy or delete copy; move transfers and nulls the source), and make `pushBack`/`resize`/`remove` placement-construct/`std::move` elements instead of `copyMemory`. Fastest safe move: swap to `std::vector` (or `std::pmr::vector` with the custom `Allocator`) until a custom container is actually needed.

### 2. `Vector::resize` reads out of bounds when growing
**File:** `Vector.hpp:41-48`

- `copyMemory(temp, mData, size * sizeof(Ty))` copies the *new* size's bytes from a buffer holding `mSize` elements → **OOB read** on growth. `VulkanSwapchain::imageViews.resize(images.size())` hits this immediately (starts with a 1-element allocation, `mSize = 0`).
- `freeMemory(mData, (mSize - 1) * sizeof(Ty), ...)` → `mSize == 0` underflows to `SIZE_MAX`, and the wrong size corrupts the memory stats.
- Never destructs elements when shrinking.

**Fix:** Copy `std::min(mSize, size)` elements; free with the size that was allocated; guard `mSize == 0`; `std::destroy` the overflowed elements on shrink.

### 3. `Vector::remove` allocates the wrong byte count → heap overflow
**File:** `Vector.hpp:75-105`

- `mData = (Ty*)allocateMemory(mSize - 1, ...)` allocates `mSize - 1` **bytes**, then `copyMemory(mData, start, index * sizeof(Ty))` writes `index * sizeof(Ty)` bytes → **heap buffer overflow**.
- No bounds check on `index` (only `index == 0` / `index == mSize - 1` are handled specially).
- Makes 2 throwaway allocations and leaks the removed element for a job that is one `memmove`.

**Fix:** Allocate `(mSize - 1) * sizeof(Ty)`; better, `std::move_backward`/`memmove` the tail down by one — one allocation, no temp buffers, bounds-check `index`.

### 4. `VulkanBuffer` — discarded/uninitialized flags, null-deref, GPU leak, never uploaded
**File:** `Renderer/Vulkan/Structures/VulkanBuffer.cpp` + `.hpp`

- `vk::BufferUsageFlagBits usageFlags;` is **uninitialized** and `usageFlags | vk::BufferUsageFlagBits::eIndexBuffer;` **discards the result** (`|`, not `|=`). Clang confirms `-Wuninitialized` on both (lines 25–26). The buffer is created with **zero usage flags** (validation rejects at bind time) and `eMapped` is never set → `bufferAllocationInfo.pMappedData` is null → `setData` does `copyMemory(nullptr, ...)` → crash.
- Bonus bug: the `Vertex` case sets `eIndexBuffer` instead of `eVertexBuffer`.
- `reinterpret_cast<VulkanContext*>(bufferInfo.backendData)` is type-unsafe; a null `backendData` (the old `Mesh` constructor path) → null deref on `context->vmaAllocator`.
- `VulkanBuffer` never stores the allocator → **no destructor, GPU buffer + allocation leak forever**.
- `VulkanRenderer::createVertexBuffer/createIndexBuffer` take `data` but **never call `setData`** → mesh data never reaches the GPU (empty buffers).

**Fix:** `usageFlags |= ...` (and `eVertexBuffer` for the vertex case); construct via a proper `VulkanContext&` parameter instead of `void*`; add a destructor calling `context.vmaAllocator.destroyBuffer(buffer, bufferAllocation)` (store the allocator or a device pointer in the buffer); have `createVertexBuffer`/`createIndexBuffer` call `setData(data, size)`.

### 5. `VulkanSwapchain` — image views never created, empty destructor, hardcoded preTransform
**File:** `Renderer/Vulkan/Structures/VulkanSwapchain.cpp` + `.hpp`

- `imageViews.resize(images.size())` is never followed by per-image `createImageView` → **all image views are null**, nothing can render.
- Destructor is empty → swapchain, `depthImage`, `depthImageAllocation`, `depthImageView` never destroyed. `resize()` does `context.swapchain.reset()` → **GPU leak + validation errors on every window resize**.
- `preTransform = vk::SurfaceTransformFlagBitsKHR::eIdentity` should be `surfaceCapabilities.currentTransform` — swapchain creation fails on systems reporting a non-identity transform.
- `chooseBestSurfaceFormat` ignores the `formats` argument (hardcoded B8G8R8A8-sRGB); `width = width;` is a no-op self-assignment (param shadows member, member never gets the clamped size).
- `minImageCount` uses the surface minimum (usually should be `min + 1`); `compositeAlpha` hardcoded `eOpaque`; `maxFramesInFLight` is dead.

**Fix:** Query `currentTransform`; create the per-image views; implement the destructor (destroy views + `vmaAllocator.destroyImage`); actually pick a supported format; remove the self-assignment; guard against 0×0 on minimize.

### 6. `ModelLoader` — OOB reads without normals/UVs, unchecked LoadObj, double-free return
**File:** `Utility/ModelLoader.cpp`

- `attrib.normals[index.normal_index * 3]` — `normal_index` is `-1` when the OBJ has no normals → **negative-index OOB read** (same for `texcoords`). Many real OBJs lack normals or UVs.
- `LoadObj` result, `warn`, `err` ignored; `shapes[0]` indexed without checking `shapes` is non-empty → crash on empty/corrupt files.
- `return Mesh{ vertices, indices };` → shallow copy (see #1) → **double-free/UAF**.
- `indices.pushBack(indices.size())` builds a sequential 0..n-1 index buffer — de-indexes the mesh, duplicating vertices and losing sharing.

**Fix:** Guard missing attributes (`attrib.normals.empty()` → zeros); check `LoadObj` return + `shapes.empty()`; build the `Mesh` members directly (no copies) once Vector is fixed; keep the original index buffer instead of re-sequencing.

### 7. `VulkanDevice` — empty destructor, unverified features/extensions
**File:** `Renderer/Vulkan/Structures/VulkanDevice.cpp` + `.hpp`

- Empty destructor → `logicalDevice` never destroyed → leak + teardown validation errors.
- Requests 1.2/1.3 features (`descriptorIndexing`, `bufferDeviceAddress`, `synchronization2`, `dynamicRendering`) **without checking `getFeatures()`** → `vkCreateDevice` fails on hardware lacking them.
- Physical-device selection loop **overwrites `physicalDevice` on every discrete GPU — picks the last, not the first** (no `break`).
- `queueFamilyIndices.isComplete()` demands dedicated compute + transfer families; fallbacks exist, but any device without a present-capable graphics queue fails the assert.
- Requests `VK_KHR_external_memory_win32` which is never used.

**Fix:** Destroy the device; validate feature support and fall back gracefully; `break` after selecting; relax queue requirements to graphics+present.

### 8. `Application` — headless mode crashes; Renderer members never initialized
**File:** `Core/Application.cpp`, `Renderer/Renderer.hpp`

- Headless leaves `window`/`renderer` null but `run()` unconditionally calls `window->update()` and `renderer->drawFrame()` → **null deref**.
- `Renderer(const RendererInfo&) {}` **ignores rendererInfo** → `width`/`height`/`appName` never set → `getWidth()` returns garbage. Clang: `-Wunused-parameter` at `Renderer.hpp:23`.
- Dead code: `bool limitFrames{false}` is always false; `runningTime`/`frameCount` set-but-unused (clang-confirmed). `RenderPacket packet{ deltaTime };` triggers `-Wmissing-field-initializers`.

**Fix:** Guard `run()` for headless; store the rendererInfo members in the base ctor; delete the dead frame-limit scaffolding or wire it up.

## 🟠 High

### 9. `KeyCodes` — `find()->second` without `end()` check → UB
**File:** `Core/Event/KeyCodes.hpp:388-396`

- `KeyCodeFromWParam` and `keyCodeToString` do `table.find(k)->second` — any key absent from the table (e.g. VK `0x2A`, `0x2B`, `0x5E`) **dereferences `end()`**. `wParam` is truncated `WPARAM → uint8_t`, so unexpected keys are reachable from real input.
- Both are `constexpr` while calling non-constexpr `std::map::find` — ill-formed per the standard, works only by compiler laxity.

**Fix:** `auto it = table.find(k); return it == table.end() ? KeyCodeID::Unknown : it->second;`. Consider a `std::array` indexed by VK code for O(1) + compile-time safety.

### 10. `Win32Window::WindowProc` — null `window` deref, dead code
**File:** `Window/Windows/Win32Window.cpp`

- Messages arriving before `WM_NCCREATE` (or a stale `GWLP_USERDATA`) leave `window == nullptr`; `WM_CLOSE`/`WM_DESTROY` deref `window->dispatcher` **before** the `if (window)` check → crash.
- `static EventDispatcher EventDispatcher{};` (line 27) is dead code — the member `dispatcher` is what is used.
- `WM_SIZE` while minimized yields 0×0 → needless swapchain recreation; the resize listener does not guard against zero extents.
- Two unused `pressed` locals (clang-confirmed, lines 146 and 183).

**Fix:** Null-check `window` at the top of the switch; delete the static; skip resize dispatch when `newWidth == 0 || newHeight == 0`.

### 11. Vulkan teardown — instance/surface/allocator never destroyed
**File:** `Renderer/Vulkan/VulkanRenderer.cpp:85`

- `~VulkanRenderer` only does `context.device = {};` — instance, surface, VMA allocator, swapchain, device all leak at shutdown (combined with #5 and #7, the whole graph leaks).

**Fix:** Destroy in reverse order (swapchain → device → allocator → surface → instance), or move to `vk::raii` / `vma::raii` wrappers which make ordering mistakes impossible.

### 12. `AssetManager` — never uploads, no query, no dedup
**File:** `Core/AssetManager.hpp`

- Because `createVertexBuffer` never uploads (#4), `loadMesh` produces **empty GPU buffers**.
- `meshMap[handle]` uses a freshly generated key but there is **no `getMesh(handle)` accessor** — the map is never read.
- No path-based dedup (same file → duplicate GPU resources); `path` passed by value; `Ref<Renderer>&` is an awkward non-const-ref parameter.
- `Game` has no access to the AssetManager (commented out in `Game.hpp`) so the asset pipeline is unreachable from game code.

**Fix:** Call `setData` after creation; add `getMesh(handle)`; cache by canonical path; take `Ref<Renderer>`; expose the manager to `Game`.

### 13. `VulkanPlatform::platformCreateVulkanSurface` — unchecked result, fragile Windows includes
**File:** `Renderer/Vulkan/VulkanPlatform.cpp`

- `auto res = ...createWin32SurfaceKHR(...)` — **`res` never checked** (clang-confirmed) → a failed surface creation returns a null surface that crashes later during device creation.
- `#define WIN32_MEAN_AND_LEAN` is a **typo** (the real macro is `WIN32_LEAN_AND_MEAN`); `#include <windows.h>` is commented out, relying on a transitive include from `vulkan.hpp` — compiles today, fragile tomorrow.

**Fix:** Check `res` and fail loudly; fix the macro name; include `<windows.h>` explicitly.

### 14. `Clock` stores `Ref<Platform>&` — reference-member landmine
**File:** `Core/Clock.h`

- `Ref<Platform>& platform;` aliases the constructor argument's Ref. Currently safe only because it binds to `Application`'s member that outlives the clock; any reassignment/destruction of that Ref → **dangling reference**.
- `float` elapsed time loses precision on long runs.

**Fix:** Store `Ref<Platform>` by value; consider `double` precision.

## 🟡 Medium

### 15. `UUID` — header-local `static` RNG + re-seed per construction
**File:** `Core/UUID.hpp`

- Namespace-scope `static random_device`/`uniform_dist` = internal linkage, **one copy per TU**; each `UUID()` re-seeds a fresh `mt19937_64` → slow and consecutive ids can correlate.

**Fix:** Function-local `static` (or `thread_local`) engine in a single TU, or a `std::atomic<uint64_t>` counter seeded once.

### 16. `Memory` — untracked allocations, stats underflow, missing allocator `operator==`
**File:** `Core/Memory.cpp`, `Core/Memory.hpp`

- `Platform::Create()` uses `std::make_shared` → bypasses the tagged allocator entirely, making the tag system inconsistent (engine Refs use `CreateRef`, platform doesn't).
- Vector's wrong-size frees (#2/#3) underflow the `stats` counters (size_t wrap).
- `Allocator<Ty>` has no `operator==` → any `std::vector<T, Allocator<T>>` fails to compile (`std::allocator_traits` requires equality).
- `Memory::shutdownMemory()` never releases the static platform Ref.

**Fix:** Route platform creation through `CreateRef`; fix the free sizes; add a stateless `operator==`; release the platform on shutdown.

### 17. `Event::toType` uses RTTI and the resize listener does not null-check
**File:** `Core/Event/Event.hpp`, `Core/Application.cpp`

- `toType` returns `{}` (nullptr) on mismatch; the `WINDOW_RESIZED` listener derefs the cast result unconditionally — safe today only because exactly one event type dispatches under that key.

**Fix:** Null-check the cast; or dispatch concrete event types and drop RTTI.

### 18. Build hygiene
**Files:** `Caldera/CMakeLists.txt`, `CMakeLists.txt`, `Defines.hpp`

- `file(GLOB_RECURSE ...)` — new files require a re-configure.
- **No `-Wall -Wextra`** on targets — a dozen real warnings (several confirming bugs above) stay silent.
- Root `CMakeLists.txt` sets `CMAKE_CXX_STANDARD 23` with a comment claiming C++20 — reconcile.
- `Defines.hpp` hardcodes `VK_USE_PLATFORM_WIN32_KHR` — Windows-only baked into an engine header.
- **No `CALEXPORT` usage anywhere** — works only because MinGW-clang auto-exports DLL symbols, so **switching to MSVC breaks the Sandbox link** until the export macro is applied to the API surface.
- `VMAImplementation.cpp`/`TinyObjLoader.cpp` have no guards around the `#define ..._IMPLEMENTATION` (fine for single TUs, but worth a comment).

## Suggested fix order (dependency-aware)

1. **Fix `Vector` (rule of five)** — or swap to `std::vector` with the custom `Allocator`. Every other fix touches it; nothing is safe until this lands.
2. **Split `Mesh` into CPU `MeshData` + renderer-owned `VertexBuffer`/`IndexBuffer`** — kills the `backendData` hack, the double-free, and the never-uploaded buffers in one move.
3. **VulkanBuffer/Swapchain/Device destructors + teardown ordering** — GPU leaks are invisible until they bite.
4. **Swapchain image views + `currentTransform`** — required before anything renders.
5. **ModelLoader bounds/error checks + KeyCodes `end()` guards** — cheap, prevent real crashes.
6. **Headless guard + Renderer member init + WindowProc null guard.**
7. **CMake `-Wall -Wextra`** so the next bugs surface at compile time.

---

## Summary

The build is green and the foundation is solid — `std::format` logger with compile-time format checks, event/listener split, tagged `Ref`/`CreateRef` allocator plumbing, and a clean Vulkan 1.3 feature chain are all good. The two things that will crash or leak first are the **custom `Vector` container** and the **GPU-ownership model** (CPU types creating GPU resources via a type-unsafe `backendData` cast). Both need addressing before the engine renders a frame.
